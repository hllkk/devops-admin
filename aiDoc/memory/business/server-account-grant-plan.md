# 服务器模块·资产账号与登录授权规划（P4 立项）

> 日期：2026-10-08 ｜ 状态：设计决策已确认（模型+技术路线+分期），未动工

## 需求

用户场景：平台用户对服务器有管理权限（监控可见性），但只希望授权他登录服务器上的某个业务账号（如 ekp、qiyuesuo 等应用账号）——**账号级登录授权**。此前讨论中曾判断「业务账号不进凭据体系」，该判断被此场景推翻修正：账号授权是业务账号进体系的硬理由。

## 模型（与共享凭据并存，职责正交）

- `server_account`（资产账号，**从属资产**，一资产多账号）：account_id / asset_id / username / secret(AES 可选托管) / is_privileged(特权账号，自动改密用) / 说明——解决「每台机器账号各不相同」（JumpServer 式）
- `server_login_grant`（登录授权三元组）：user_id × asset_id × account_id + expires_at + 说明
- **监控可见性（casbin/数据权限）与登录授权是两个正交权限轴**：资产管理员可以无登录授权，登录授权用户可以无监控权限
- `server_credential`（slice1 已落地）语义不变：仅**平台管理通道**（SSH 公钥用户名/BMC/DB/SNMP），平台用户不可见

## 技术路线决策：个人公钥下发（非 SSH 会话代理）

- 授权 = 把**用户个人公钥**写入目标机对应账号的 authorized_keys；撤销 = 删行
- 密码**不托管**：契合「root 密码仅内存态」的公钥架构，改密零耦合（轮换服务器密码不影响平台）
- 与平台公钥装 agent 同源：slice2 的 SSH 公钥部署函数按「**可写任意公钥**」设计（平台公钥/用户公钥同函数），P4 零返工
- 会话审计录像/命令审计：直连 SSH 不经平台审计弱——真有需求时再补 SSH 代理层（与公钥方案不互斥，代理可用个人密钥）
- 自动改密（特权账号 SSH 执行 passwd + 成功后更新托管行）：更后，按需评估

## 分期

- P4 slice10：`server_account` + `server_login_grant` + 个人中心用户公钥登记
- P4 slice11：授权公钥下发（复用 slice2 SSH 通道）+ 授权到期/撤销

## SSH 凭据语义同步收敛（同日决策）

SSH 凭据模板去掉 password 字段——root 密码仅内存态（既定决策），安装后公钥认证，SSH 密码不落库；SSH 凭据=公钥认证用户名。BMC/DB/SNMP 存密码是协议本质（AES+掩码+审计兜底），不受影响。
